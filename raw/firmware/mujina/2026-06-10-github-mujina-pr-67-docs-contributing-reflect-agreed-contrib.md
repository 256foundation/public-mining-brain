## Description

In a [recent dev call](https://forum.256foundation.org/t/mujina-dev-call/31/2) a few agreements were made on how to collaborate, so I thought of reflecting them in the repo's contributing and readme docs:

- Distinguish two workflows: bugs go Discussion → Issue → PR; features go Discussion → Draft PR, staying draft until ready to merge
- Broaden the simple-fix exception to include clear, self-contained bug fixes, not just cosmetic changes
- Reframe draft PRs as the expected state for in-progress features, not just an optional early-feedback tool
- Add the Mujina forum for user-oriented support; clarify that Telegram is ephemeral and decisions belong on GitHub
